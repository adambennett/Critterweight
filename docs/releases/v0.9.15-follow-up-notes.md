# Follow-up research and menu audit — v0.9.15 preview 2

## Code-capable mods

The current data-only statement is accurate: ModManager's allowlist and script-capability
checks reject script files, native libraries, engine scenes/resources and PCKs. This is a
chosen trust model, not a Godot engine limitation. Data packages can still change fighters,
abilities, rules, arenas and presentation through the exposed content schemas.

A limited opt-in trusted-script prototype is plausible in roughly 1–2 engineering weeks.
A supported mod API, documented hooks and examples, load-order/version handling, save and
replay compatibility, multiplayer handshakes and diagnostic tools are more like 4–8+ weeks.
These are planning estimates, not a scoped commitment. A secure sandbox is a larger project;
ordinary GDScript can access the OS, so accepting .gd files alone would not create one.

A sensible first step would be versioned offline gameplay hooks in explicitly trusted local
mods, with code packages never silently received from servers. Keep the existing data route
for portable/simple content. No code-mod behavior was changed in this preview.
Engine reference: https://docs.godotengine.org/en/stable/tutorials/export/exporting_pcks.html
