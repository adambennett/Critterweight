# Cage Rules guest import

The owner requested Jeremy's fighter as the seventh Critterweight fighter (v0.9.15) and Jeremy's referee for the Cage Rules preset (v0.9.16). This is the reproducible build adapter for both. It extracts the original procedural mesh, rig, poses and strike definitions; it does not run a second game engine at runtime.

## Rebuild

From the repository root, run `node tools/cage_rules/import.js`, then Godot's headless asset import. This rewrites only:

- `game/content/core/creatures/f_varga.json` and `game/assets/models/creatures/f_varga.glb` (Varga);
- `game/assets/models/referee/cage_referee.glb` and `game/assets/data/cage_referee.json` (the referee, view-only).

The build is deterministic: two runs give identical bytes. `source-manifest.json` lists the SHA-256 of every output; compare after a rebuild (Varga's two files have not changed since v0.9.15).

`source/` contains copies of `MMAsim/js/{sim,physics,render}.js` and `MMAsim/lib/three.min.js` from the owner's Cage Rules project, identical to the originals except for line endings: the source checkout uses CRLF, this repository stores text as LF (`.gitattributes`). `source-manifest.json` records the original paths with the hashes of both forms (`sha256`/`bytes` = the CRLF source working tree, `retained_sha256`/`retained_bytes` = the LF copies here); converting a retained file back to CRLF reproduces the source hash. The source project is not edited. Three.js is MIT licensed; its notice is in `source/LICENSE-three.txt`. Rapier and PeerJS are not imported. The build uses only Node's built-in modules and this retained Three.js bundle.

## Adaptations

- Original 11-segment fighter, smooth skin, face, shorts and gloves become a glTF skin bound to Critterweight's physics segments. Foot mesh weights merge into the source shin segments.
- Source strike timings, stamina costs and keyed rotations are retained. Body scale is 1.06. Damage/lunges/active-window adjustments are explicit in the adapter for this game's balance and timestep.
- Arm FK targets become IK chains for opponent-height retargeting. Kick keys retain source joints with additional arm clearance. Pelvis yaw/tilt converts to the target rotation convention. Mirrored variants supply southpaw.
- Original source poses supply stance, guard, low shell and raised-shin check. Walking uses the target engine's gait.
- New abilities, JUICE, elemental buildup, native grapple/throw rules, UI prompts and controller inputs integrate with Critterweight. Ground positions/submissions are outside this port.

### Referee (v0.9.16)

- The referee is render.js's own `new FighterModel(scene, 0x1e2028, 0xc99a74, 2, { ref: true })`: the fighter's procedural body and bind skeleton (body width 1, short grey hair) dressed as the referee (shirt, slacks, shoes, open nitrile hands). The adapter checks his bind frames against Varga's and reuses Varga's bone pivots and scale.
- render.js keeps the referee's poses in its closure. The adapter extends the export line **in memory only** (the retained file is unchanged; an assertion fails if the export line is not found exactly once) to read `REF_POSES`, `LINE_POSES`, `ceremonyTimes`, the referee constants (`REF_CAGE`, `KD_HOLD`, `REF_SPEED`, `REF_ROOM`, `LUNGE_*`, `LINE_X`, `KD.STAY`) and the rig constants of the kinematic pose evaluator.
- `cage_referee.json` holds that data plus a valid view-only body (Varga's segments, leg chains and stance), the list of surfaces the original draws double-sided, and baked segment transforms: the original `FighterModel.update` evaluated in Node for every referee pose, the animated hands, a placement, a pose blend and a step. `game/src/test/core/test_referee_view.gd` checks the GDScript port (`game/src/view/referee_pose.gd`) against them.
- He is presentation only (`game/src/view/referee_view.gd` ports `class Referee`'s director to Critterweight's arenas and match phases). His data stays outside `game/content`, so he is not a gameplay creature and the multiplayer content hash is unchanged.

`knell-build.json` records the separate original Knell model build measurements; Knell is generated by the existing forge, not Cage Rules.

The original source files are build-only and are not exported in the game PCK. The original fighter's and referee's derived models, moves and poses are exported under the owner's requested reuse authorization. This does not assign a new licence to Jeremy's source code.
